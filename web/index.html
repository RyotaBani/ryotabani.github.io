    Webページが表示されるまでの流れ
    
    
    ブラウザにURLを入力してからページが表示されるまでには、大きく分けて4つの段階があります。
    
    
      
      
    1. URLを読み取る：どの方法で、どのコンピュータの、どのファイルを取りに行くかを決める
      2. 
      
    2. DNSで名前を調べる：ホスト名（www.example.com など）を、IPアドレスに変換する
      3. 
      
    3. 接続する：TCPで相手と接続し、https なら TLS で暗号化の準備をする
      4. 
      
    4. HTTPでやり取りする：ページを要求し（リクエスト）、HTMLや画像を受け取る（レスポンス）
      5. 
    
    
    
    これらはふつう1秒もかからずに終わるので、利用者が気づくことはありません。「表示までの流れ」では、この一瞬のやり取りを1つずつ止めて見られるようにしています。
    

    
    URLのしくみ
    
    
    URL（Uniform Resource Locator）は、インターネット上の情報の場所を表す書き方です。https://www.example.com/news/index.html なら、https がスキーム（やり取りの方法）、www.example.com がホスト名（相手のコンピュータの名前）、/news/index.html がパス（サーバの中の場所）です。
    
    
    ポート番号は、1台のコンピュータの中で、どのサービスと通信するかを表す番号です。省略したときは、http なら 80 番、https なら 443 番が使われます。? の後ろのクエリはサーバに渡す追加の情報、# の後ろのフラグメントはページの中の位置を表します。フラグメントはサーバには送られず、ブラウザの中だけで使われます。
    

    
    DNS：名前からIPアドレスを調べる
    
    
    インターネットで相手にデータを届けるには、IPアドレスが必要です。しかし、数字の並びは人間には覚えにくいので、www.example.com のようなドメイン名が使われます。ドメイン名とIPアドレスを対応させるしくみが DNS（Domain Name System）です。
    
    
    DNSの情報は、1か所にまとめて置かれているのではありません。ドメイン名は右から順に「ルート（.）→ com → example.com → www」という木のような階層になっていて、それぞれの階層を担当するDNSサーバが、自分の範囲だけを管理しています。これを分散データベースといいます。
    
    
    名前を調べるとき、パソコンやスマートフォンは、まず決められたフルサービスリゾルバ（キャッシュDNSサーバ）にたずねます。リゾルバは、階層のいちばん上のルートサーバからたずね始め、「com のサーバに聞いて」「example.com のサーバに聞いて」と教えてもらいながら、最後にその名前を管理している権威DNSサーバから答えを得ます。ルートサーバは13系列あり、そのうちの1つ（M ルート）は、日本の WIDE プロジェクトと JPRS が共同で運用しています。
    
    
    キャッシュとTTL
    
    
    毎回ルートサーバからたずねていては、時間がかかり、ルートサーバにも負担が集中します。そこでリゾルバは、一度調べた答えをキャッシュとして一定時間覚えておきます。覚えておいてよい時間は、答えに付いている TTL（Time To Live）で決まります。「DNSで名前を調べる」で同じ名前を2回たずねると、2回目は問い合わせが0回になることを確かめられます。
    
    
    レコードの種類
    
    
    
      
    種類表す内容
    
      
    AIPv4アドレス
    
      
    AAAAIPv6アドレス
    
      
    MXそのドメインあてのメールを受け取るサーバ
    
      
    CNAME別名（ほかの名前を指す）
    
      
    NSそのドメインを管理するDNSサーバ
    
    
    
    
    電子メールを送るときも、DNSが使われます。送信側のメールサーバは、あて先のドメインの MX レコードを調べて、どのサーバに届ければよいかを知ります。電子メールのしくみもあわせて確かめてみましょう。
    

    
    TCP：確実に届けるための接続
    
    
    IPアドレスが分かると、ブラウザはWebサーバと TCP の接続を作ります。TCP は、データが届いたかを確認し、届かなければ送り直し、順番を並べ直して、データを確実に届けるためのプロトコルです。接続を始めるときは、SYN → SYN＋ACK → ACK の3回のやり取りを行います。これを3ウェイハンドシェイクといいます。
    
    
    https の場合は、続いて TLS の手順に入ります。ブラウザとサーバが暗号化の方式と鍵を決め、サーバはサーバ証明書を送ります。ブラウザは、信頼できる認証局の電子署名が付いているかを調べて、通信相手が本物かどうかを確かめます。ここから先の通信は暗号化されるので、途中で盗み見られても内容は読めません。暗号化のしくみは暗号のしくみで体験できます。
    

    
    HTTP：リクエストとレスポンス
    
    
    HTTP（HyperText Transfer Protocol）は、ブラウザとWebサーバがやり取りするための決まりです。ブラウザは「GET /news/ HTTP/1.1」のようなリクエストを送り、サーバは「HTTP/1.1 200 OK」のようなレスポンスを返します。レスポンスの本文には、ページの中身である HTML が入っています。
    
    
    HTMLの中には、見た目を決める CSS や画像のファイルの場所が書かれています。ブラウザは HTML を読みながら、必要なファイルを次々に要求します。1つのページを表示するために、何十回ものリクエストが送られることもめずらしくありません。
    
    
    主なメソッドとステータスコード
    
    
    メソッドは、サーバに何をしてほしいかを表します。GET は情報を取得し、POST はフォームの入力内容などを送ります。ステータスコードは結果を表す3けたの数で、最初の数字で分類されます。
    
    
    
      
    分類意味例
    
      
    1xx情報（処理の途中）100 Continue
    
      
    2xx成功200 OK
    
      
    3xxリダイレクト301 Moved Permanently
    
      
    4xxクライアント側のエラー403 Forbidden、404 Not Found
    
      
    5xxサーバ側のエラー500 Internal Server Error
    
    
    

    
    使い方
    
    
      
      
    • 表示までの流れ：「次へ」で1つずつ進みます。「DNSのキャッシュがある」「暗号化しない http」を切りかえて、やり取りの回数がどう変わるかを比べましょう。
      • 
      
    • DNSで名前を調べる：名前とレコードの種類を選んで問い合わせます。図の番号は、たずねた順番です。shop.example.com の A レコードをたずねると、別名（CNAME）をたどるようすが分かります。
      • 
      
    • URLとHTTP：URLを入力すると部分に分けて表示します。パスとメソッドを選んで送ると、リクエストとレスポンスの中身と、ステータスコードの意味を確かめられます。
      • 
    
    
    
    このページの www.example.com や 203.0.113.10 は、説明や例示のために予約されている名前とアドレスです。実際の通信は行っていません。
