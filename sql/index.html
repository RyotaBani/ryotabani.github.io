データベースとは

たくさんのデータを、あとから探したり、追加したり、書きかえたりしやすいように、決まった形で整理して蓄えたものをデータベースといいます。学校の名簿や成績、図書館の蔵書、ネットショップの商品と注文、交通系ICカードの利用記録など、身の回りの情報システムの多くは、裏側でデータベースを使っています。

データベースを管理するソフトウェアをDBMS（データベース管理システム）といいます。DBMS は、データを決まった構造で蓄えるだけでなく、データの矛盾が起きないように保つこと（一貫性）、必要なデータを効率よく取り出すこと、たくさんの人が同時に使っても困らないようにすること、障害が起きたときに元に戻すことなどを受け持ちます。

リレーショナルデータベース

データベースにはいくつかの種類がありますが、最も広く使われているのがリレーショナルデータベース（関係データベース）です。データを、行と列からなる表（テーブル）で管理します。

  • 列（フィールド）：「氏名」「組」のような項目。表の上に並ぶ見出しです
  • 行（レコード）：1件分のデータ。このページの「生徒」の表なら、生徒1人分が1行です
  • 主キー：その行を1つに決めるための列。「生徒」の表では学籍番号です。氏名は同じ人がいるかもしれないので、主キーには向きません
  • 外部キー：ほかの表の主キーを指す列。「生徒」の表の部活IDは、「部活」の表の部活IDを指しています

外部キーを使うと、表どうしを関連づけられます。生徒の表に部活の名前や活動場所を書かなくても、部活IDを手がかりに部活の表から取り出せるのです。

選択・射影・結合

リレーショナルデータベースでは、表から必要なデータを取り出すために、次の3つの関係演算がよく使われます。

操作内容SQL での書き方
選択条件に合う行だけを取り出すWHERE 組 = 2
射影必要な列だけを取り出すSELECT 氏名, 組
結合共通の列で2つの表をつなぐJOIN 部活 ON 生徒.部活ID = 部活.部活ID

「選択・射影・結合」のタブでは、これらをボタンで1つずつ試せます。操作をするたびに、同じ結果を作る SQL 文が下に表示されます。たとえば、生徒の表と部活の表を結合すると、部活IDが空の生徒（斎藤）は、相手の表に同じ値がないので結果に入りません。

SQL の基本

リレーショナルデータベースを操作するための言語が SQL です。SQL は国際規格（ISO/IEC 9075）で定められていて、多くの DBMS で同じように使えます。データを取り出すときは SELECT 文を使い、次の順に書きます。

SELECT 取り出す列
FROM 表
JOIN 別の表 ON つなぐ条件
WHERE 行の条件
GROUP BY まとめる列
HAVING まとめた結果の条件
ORDER BY 並べる列 DESC
LIMIT 件数;
  • WHERE では、=、<>（等しくない）、>= などで比べ、AND・OR・NOT で組み合わせます。LIKE '%木%' は「木」をふくむ、という意味です
  • GROUP BY を使うと、同じ値の行をまとめて、COUNT（件数）、SUM（合計）、AVG（平均）、MAX（最大）、MIN（最小）で集計できます
  • ORDER BY は並べ替えです。ASC は小さい順（省略できます）、DESC は大きい順です

SQL には、データを追加する INSERT、書きかえる UPDATE、削除する DELETE などもあります。このページでは、データを壊さずに試せるよう、検索の SELECT 文だけを実行できるようにしています。

正規化と異常

1枚の表にすべてを書きこむと、同じ情報が何度も出てきます。たとえば、部活の活動場所を生徒1人ずつの行に書くと、同じ部活の生徒の数だけ活動場所がくり返されます。このとき、次のような困りごと（異常）が起きます。

  • 更新時異常：活動場所が変わったとき、全部の行を書きかえないと、古い場所と新しい場所が混ざって矛盾する
  • 削除時異常：ある部活の最後の部員の行を消すと、部活があったことまで消えてしまう
  • 挿入時異常：部員がまだいない部活を登録しようとしても、主キーの学籍番号が空になるので登録できない

こうした問題が起きないように、表を適切に分けることを正規化といいます。くり返しをなくして1つのセルに1つの値だけにした形を第1正規形、主キーの一部だけで決まる列を別の表に分けた形を第2正規形、主キー以外の列で決まる列をさらに分けた形を第3正規形といいます。正規化を進めると、どの情報も1か所だけに書かれるようになり、書きかえは1回で済みます。「正規化」のタブで、表の形を変えながら同じ操作をして、結果を比べてください。

たくさんの人が同時に使うとき

銀行の口座や座席の予約のように、たくさんの人が同時に同じデータを書きかえる場面では、処理の順番によっては残高や空き席の数が合わなくなるおそれがあります。DBMS は、ひとまとまりの処理（トランザクション）を、すべて行うか、まったく行わないかのどちらかにしたり、だれかが書きかえている間はほかの人が同じデータを書きかえられないようにしたり（排他制御）して、データの整合性を保っています。

表の形ではないデータベース

データベースは表の形のものだけではありません。項目（キー）と値（バリュー）の組でデータを記録するキー・バリュー形式のデータベースなどもあり、こうした表以外の形式に対応したデータベースは、まとめて NoSQL と呼ばれます。大量のデータを扱う場面で使われています。

使い方

  • SQLで検索する：見本のボタンを押すか、SELECT 文を書いて「実行」を押します。右の表の一覧で、表の名前を押すと中身が見られます。書き方がまちがっているときは、どこがおかしいかを表示します。
  • 選択・射影・結合：表を選び、条件や列を決めてボタンを押します。条件に合う行や残る列が黄色になってから、結果の表に変わります。
  • 正規化：非正規形から第3正規形までの表の形を切りかえて、活動場所の変更や部員の削除などを試します。

このページの生徒や成績のデータは、すべて架空のものです。小数は小数第3位を四捨五入して表示しています。
