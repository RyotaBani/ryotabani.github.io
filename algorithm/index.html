オーダー記法

データの個数を n としたとき、処理にかかる回数がどう増えるかを表す書き方を オーダー記法といい、O(n) のように書きます。 細かい係数は無視して、増え方の性質だけを見るのが特徴です。 データが少ないうちは差が出なくても、大きくなると決定的な違いになります。

アルゴリズムとは

ある問題を解くための、決まった手順のことをアルゴリズムといいます。料理のレシピに似ています。同じ料理でも、作り方は何通りもあり、手際のよい手順とそうでない手順があります。

コンピュータのプログラムも同じです。同じ答えを出すのでも、手順の選び方で処理時間が何百倍も変わることがあります。だからアルゴリズムを学ぶ意味があるのです。

アルゴリズムに求められる条件は3つです。手順が明確であること、必ず終わること、正しい答えが出ることです。

探索 ― 目的のものを見つける

線形探索

最も素直な方法です。先頭から順に、1つずつ調べていきます。見つかったら終了、最後まで見つからなければ「ない」と答えます。

単純で、どんなデータにも使えるのが利点です。並んでいなくても構いません。ただし、データが多いと時間がかかります。1000個のデータなら、最悪1000回調べることになります。

二分探索

データが小さい順に並んでいるとき使える方法です。手順はこうです。

  1. まん中を調べる
  2. 目的の数より大きければ、後ろ半分は捨てる
  3. 小さければ、前半分を捨てる
  4. 残った範囲で、また1に戻る

1回調べるごとに、探す範囲が半分になります。これが決定的な差を生みます。

1000個 → 500 → 250 → 125 → 63 → 32 → 16 → 8 → 4 → 2 → 1（10回）

1000個のデータでも、たった10回で見つかります。線形探索なら最悪1000回かかるところです。データが100万個になると、線形探索は100万回、二分探索は20回。差は歴然です。

ただし条件があります。あらかじめ並んでいることです。並んでいないデータには使えません。辞書や電話帳で目的の項目をすぐ探せるのは、五十音順に並んでいるからです。

整列 ― 順番に並べかえる

二分探索を使うには、まず並べる必要があります。この並べかえを整列（ソート）といいます。

交換法（バブルソート）

となり合う2つを比べ、順序が逆なら入れかえます。これを繰り返すと、大きい数が泡のように後ろへ移動していきます。

仕組みが分かりやすい反面、効率はよくありません。n個のデータに対して、比較の回数はおよそ n² に比例します。

選択法

まだ並んでいない範囲から最小のものを探し、先頭と交換します。次は2番目から同じことを繰り返します。

入れかえの回数が少ないのが特徴です。比較は多いものの、交換は最大でもn回で済みます。

挿入法

トランプを手札に並べるときの動きに似ています。左から順に、すでに並んでいる部分の適切な位置へ差し込んでいきます。

すでにある程度並んでいるデータに対しては、非常に速く動きます。

もっと速い方法

実用的なプログラムでは、クイックソートやマージソートといった方法が使われます。データを分割して個別に処理する考え方（分割統治法）を使い、n log n に比例する回数で並べられます。

データが100万個のとき、n² なら1兆回ですが、n log n なら約2000万回です。5万倍の差になります。

計算量という考え方

アルゴリズムの効率を表すのに、計算量という概念を使います。データの個数 n が増えたとき、必要な処理回数がどう増えるかを見ます。

記法増え方例
O(1)データが増えても変わらない配列の何番目かを取り出す
O(log n)とてもゆっくり増える二分探索
O(n)比例して増える線形探索
O(n log n)やや速く増えるクイックソート
O(n²)急激に増えるバブルソート

大切なのは、データが少ないうちは差が出ないという点です。10個程度なら、どのアルゴリズムでも一瞬で終わります。違いが表れるのは、データが大きくなったときです。

現代では、扱うデータが膨大になっています。検索エンジンは数百億のページを、SNSは数十億の利用者を扱います。この規模になると、アルゴリズムの選択が実現できるかどうかを決めてしまいます。

身近なアルゴリズム

アルゴリズムは、日常のあちこちで動いています。

  • 地図アプリの経路探索：ダイクストラ法などで最短経路を求めます
  • 検索エンジン：膨大なページから関連するものを高速に見つけます
  • おすすめ表示：似た好みの人を探し、その人が好きなものを提示します
  • 画像の圧縮：人が気づきにくい情報を選んで削ります

どれも、単に計算が速いコンピュータがあれば済む話ではありません。賢い手順があってこそ、現実的な時間で答えが出せるのです。

アルゴリズムの表し方

手順を人に伝えるには、書き表す方法が必要です。いくつかの方法があります。

方法特徴
流れ図（フローチャート）記号と矢印で処理の流れを図にする。全体像がつかみやすい
擬似言語プログラムに近い書き方だが、特定の言語には縛られない
アクティビティ図並行する処理も表現できる

流れ図では、記号の意味が決まっています。長方形は処理、ひし形は条件による分岐、平行四辺形はデータの入出力です。共通テストでも、擬似言語を使った問題が出題されています。

3つの基本構造

どんなに複雑なプログラムも、3つの構造の組み合わせで書けることが知られています。

  • 順次：上から順に実行する
  • 選択（分岐）：条件によって処理を分ける
  • 反復（繰り返し）：条件が成り立つ間、同じ処理を繰り返す

この3つだけで足りるという事実は、構造化定理として証明されています。だから、まずこの3つを確実に理解することが、プログラミングの土台になります。

使い方

  • 探す：線形探索と二分探索を切り替えて、調べる回数を比べられます。「1回ずつ進める」で手順を追えます。
  • 並べる：3つの整列方法を動かして、比較回数と交換回数を比べられます。
  • 計算量を比べる：データの個数を変えると、処理回数がどう増えるかが分かります。
